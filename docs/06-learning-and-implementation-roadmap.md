# Go 重构学习与实施路线

本项目采用模块化单体作为学习和开发起点。先在一个 Go 进程内明确业务模块、依赖边界和生命周期，再根据指标决定是否拆分服务。

每个阶段都包含四个部分：业务目标、Go 学习内容、中间件学习内容和验收方式。实现过程中以边实现边讲解为主，先理解调用链和数据流，再编写代码，最后通过测试和故障演练验收。

## 当前基础

已经完成：

- Go module 和项目目录。
- Gin HTTP 服务和统一响应。
- 请求 ID、访问日志、panic recovery。
- GORM、MySQL 连接池和事务。
- go-redis、Redis Lua 和 Redis outbox。
- kafka-go、Kafka Producer、Consumer 和 DLQ。
- 秒杀 HTTP 接口、异步下单和订单查询。
- Redis Sentinel、Kafka 积压恢复和自动库存补偿验证。
- 百万级和千万级 HTTP 压测。

当前秒杀模块作为后续所有模块的并发和异步实践样例。

## 阶段 0：项目基线和学习方法

### 业务目标

记录当前架构、秒杀验收结果、后续优化点和模块实现顺序。

### Go 学习内容

- `go.mod` 和依赖管理。
- package、internal 和 cmd 的作用。
- struct、方法、构造函数和指针。
- error、`errors.Is`、`errors.As` 和 error wrapping。
- `context.Context` 的超时和取消。
- goroutine、channel 和 `sync.WaitGroup`。
- `go test`、`go test -race`、`go vet` 和基准测试。

### 中间件内容

- Redis、Kafka 和 MySQL 的职责边界。
- 同步请求和异步事件的区别。
- 至少一次投递和业务幂等。
- 数据库事实和缓存状态的关系。

### 验收方式

- 能从 `submit` 读到 Redis Lua。
- 能从 `RunWorkers` 读到应用启动和关闭流程。
- 能解释一次订单从 HTTP 到 MySQL 的完整链路。
- 能独立运行单元测试、压测和故障脚本。

状态：已完成。

## 阶段 1：用户、登录和鉴权

### 业务目标

实现手机号验证码注册和登录、Token 生成与撤销、用户资料查询和通用登录鉴权。真实登录会话直接访问秒杀接口。

### Go 学习内容

- Gin 路由分组和中间件。
- Handler、Service、Repository 分层。
- 请求 DTO 和数据库 Model 分离。
- 参数校验和统一错误码。
- `crypto/rand` 生成验证码和 Token。
- HTTP Authorization Header 和 Context 用户信息。
- 使用两个 API 实例验证并发与共享状态。

### 中间件内容

- Redis Hash 保存登录态。
- Token TTL 和续期。
- MySQL 用户唯一索引。
- 登录接口限流和错误次数控制。

### 验收方式

- 登录后可以访问秒杀接口。
- 未登录请求返回统一的未授权错误。
- Token 过期后不能访问受保护接口。
- 多个 API 实例共享 Redis 登录态。

状态：已完成，见[用户、登录和鉴权](07-user-authentication.md)。

## 阶段 2：商户、店铺和缓存

### 业务目标

实现店铺查询、店铺分类、商户信息和后台店铺维护，为本地生活主业务建立基础数据。

### Go 学习内容

- GORM 查询、分页和事务。
- Repository 查询封装。
- Service 中的业务校验。
- Gin 参数绑定和响应 DTO。
- 缓存穿透、缓存击穿和缓存雪崩。
- 空值缓存和缓存 TTL。

### 中间件内容

- Redis String 缓存店铺详情。
- Redis TTL 和缓存更新策略。
- MySQL 索引设计。
- 缓存与数据库的一致性处理。

### 验收方式

- 店铺查询接口可以正常分页。
- 热门店铺命中 Redis 缓存。
- 店铺更新后缓存能够正确失效或刷新。
- MySQL 不可用时接口能返回明确的依赖错误。

状态：已完成，见[店铺、分类和详情缓存](08-shop-and-cache.md)。

实现优惠券创建、活动配置、库存初始化、活动时间控制和普通订单查询，补齐秒杀模块依赖的业务管理入口。

- 幂等接口设计。

### 中间件内容

- Redis 活动库存预热。

- Kafka 订单事件版本化。

### 验收方式

- 可以通过管理接口创建活动并初始化库存。

- 一个用户只能成功创建一笔活动订单。
- 秒杀接口不再依赖手工执行准备命令。

状态：已完成，见[优惠券、活动和订单查询](09-voucher-and-order.md)。

## 阶段 4：秒杀业务完整化

### 业务目标

将当前秒杀样例接入正式用户、优惠券和订单模块，完善订单状态查询、取消、超时和异常订单处理。

### Go 学习内容

- 跨模块接口设计。
- 领域事件和事件 Schema。
- 后台任务生命周期。
- 优雅停机和任务取消。
- 并发控制和重试策略。
- 结构化日志和链路字段。

### 中间件内容

- Kafka 消费组和分区。
- Kafka offset 提交时机。
- DLQ 和死信审计。
- Redis outbox 和租约。
- MySQL 最终事实与 Redis pending 状态。

### 验收方式

- 正式用户登录后可以参与秒杀。
- 订单状态可以从 pending 转为 confirmed。
- Kafka 重启后 pending 订单可以恢复。
- 重复 Kafka 消息不会生成重复订单。
- 库存异常可以进入审计和补偿流程。

状态：已完成，见[秒杀订单生命周期](10-order-lifecycle.md)。

## 阶段 5：博客、点赞、关注和附近商户

### 业务目标

逐步实现内容发布、点赞、关注关系、关注 Feed、附近商户和签到等 Redis 业务。

### Go 学习内容

- Redis 数据结构选择。
- 分页和游标。
- Sorted Set、Set、Hash、Bitmap 和 GEO。
- Feed 推送与拉取模型。
- 数据库和缓存联合查询。
- 接口幂等和重复点赞处理。

### 中间件内容

- Redis Sorted Set 实现时间线。
- Set 实现关注关系和去重。
- GEO 实现附近商户。
- Bitmap 实现签到。
- Kafka 事件在内容和通知模块中的应用。

### 验收方式

- 发布内容后可以查询和分页。
- 点赞和取消点赞具备幂等性。
- 关注和取关状态正确。
- Feed 查询不会重复返回内容。
- 附近商户和签到功能通过 Redis 数据核对。

状态：已完成，见[博客、关注、附近店铺和签到](11-social-and-discovery.md)。

## 阶段 7：API 和 Worker 拆分

### 业务目标

将秒杀 API 和后台 Worker 拆成独立进程，并验证独立扩容和独立发布。

### Go 学习内容

- 多进程服务入口。
- 进程级健康检查。
- 配置拆分和环境管理。
- 服务关闭顺序。
- Docker 镜像和部署配置。
- 服务间故障隔离。

### 中间件内容

- Kafka Consumer 独立部署。
- Redis 连接池和主从发现。
- Worker 组扩容。
- Kafka 分区与 Worker 数量匹配。

### 验收方式

- API 重启不会丢失 Redis outbox。
- Worker 重启可以继续消费 Kafka。
- API 和 Worker 可以独立扩容。
- Worker 故障不会阻止新请求进入 Redis。
- 部署和回滚流程可以重复执行。

状态：待开始。
